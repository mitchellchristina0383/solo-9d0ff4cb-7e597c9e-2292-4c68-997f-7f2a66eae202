# 磁带机取回模拟器（tape-drive-sim）

用 FastAPI 模拟值班室的全库磁带流程：

1. 送检前在库目录登记**全库副本目录**（至多 12 卷）；
2. 按卷申请**整批下架**（送检），通过后卷立即离线；检毕可**逐卷归还**；
3. 开工取回待取文件，给出**装带 + 回卷总次数最少**的读取顺序；
   值班员逐步回报读带结果，系统按带头新位置重排剩余文件。

## 运行

```bash
docker compose up --build      # 服务监听 8000 端口
# 浏览器打开 http://127.0.0.1:8000/docs （Swagger UI）逐步操作
```

本地开发（无 Docker 时）：

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --port 8000
.venv/bin/pytest tests/ -q                    # 单元/集成测试
.venv/bin/python scripts/walkthrough.py       # 对运行中的服务走一遍完整值班流程
```

## 值班流程与接口

| 接口 | 说明 |
| --- | --- |
| `POST /library` | 登记全库副本目录（≤12 卷）。无作业、无送检卷时可重新登记整体替换 |
| `GET /library` | 卷的在线/送检状态、每份副本是否可读、下架记录、事件流水、占用卷 |
| `DELETE /library` | 清除目录（要求无作业、无送检卷） |
| `POST /removals` | 按卷申请**整批下架**。通过即全部离线；否则整批退回，返回受影响文件与占用卷 |
| `POST /removals/{id}/returns` | 按下架申请归还一卷送检磁带（可逐卷、可乱序） |
| `POST /returns` | 按卷号归还（自动归属其下架申请） |
| `POST /jobs` | 开工：从库目录快照待取文件**当时在线且未报坏**的全部副本，返回最优计划 |
| `GET /plan` | 按当前带头位置重算最优计划，`next_step` 即下一步要回报的读带步骤 |
| `POST /receipts` | 回报**当前计划第一步**的读带结果（`ok` / `failed`），返回重排后的计划 |
| `GET /state` | 当前卷、带头、待取/已取/无副本文件、停用副本、**占用卷**、累计执行次数 |
| `DELETE /job` | 作废当前作业（释放全部卷占用；目录与坏副本标记保留） |

### 规则落实（`app/state.py`）

- **一个仓库、一把锁**：登记目录、下架审批、归还、开工、回执、作废都在
  `JobStore` 的同一把可重入锁内完成“校验 + 写入 + 生成返回快照”。
  审批/归还与开工/回执交错时，结果等价于某个串行顺序，核算与下架一起生效；
  HTTP 层只处理锁内生成的只读快照。
- **最后一份可读副本**：下架申请若使某文件在“在线且未报坏”的副本集合变为空，
  **整批退回且不改变任何卷的状态**，409 响应列出 `affected_files`。
  批次里只要有一卷仍在送检（`already_offline_volumes` 非空）也整批退回，
  避免重复申请打乱逐卷归还的归属。
- **占用卷**：开工后，待取文件的每份可读副本都占用所在卷（不只是计划里下一步
  要读的那卷），直到文件取回、该副本报坏或作业作废；申请含占用卷则整批退回，
  409 响应列出 `occupied_volumes` / `occupied_files`。
- **开工快照**：作业只纳入开工时在线且未报坏的副本；之后归还的卷不会补进
  已开工的作业（重新开工才纳入）。
- **坏副本两处生效**：`failed` 回执既停用作业内副本，也把库目录中同一副本永久
  标为不可读（后续下架核算不再把它当作该文件的最后一份）；重新登记目录时同一
  `(文件, 卷, 序号)` 的坏标记保留。
- **审批通过立即离线**；若当前挂载卷被下架，带头状态一并复位（`drive_reset` 事件）。
- **只用当前计划第一步的回执更新进度**：不符的回执 409 并附期望步骤，状态不变。
- **失败也推进带头**：成功或失败，带头都推进到该步骤的卷内序号（跨卷视为装带已发生）。
- **每步重排**：每张回执生效后按新带头位置重新规划，并列出已无副本可读的文件。

### 代价模型与规划算法（`app/planner.py`）

- **装带**：挂载一卷计 1 次；当前已挂载的卷继续读不计；装带后带头在卷首。
- **读带**：只能向序号增大方向读；同卷内按序号升序读不需要回卷。
- **回卷**：在当前卷上需要读比带头位置更小的序号时，回卷 1 次（回到卷首再升序读）。
  因此每卷至多回卷 1 次，且只有“当前已挂载卷”可能被迫回卷。

卷数 ≤ 12，**精确枚举**所有非空卷子集（≤ 4095 个）：

1. 子集须覆盖全部待取文件（每文件至少一个可用副本落在子集内）；
2. 代价 = 装带数 + 回卷数。装带数 = 子集卷数（当前卷在子集内则减 1）；
   回卷 = 1 当且仅当某文件在子集内的副本**全部**落在当前卷且全部低于带头；
3. 取代价最小者；平局依次按装带更少、用卷更少、位掩码更小裁决（确定性）；
4. 副本指派：优先非当前卷的副本，其次当前卷带头之后的副本，最后才回卷读；
   读取顺序：当前卷最先（避免卸下再装），卷内升序，当前卷低于带头的部分
   排在回卷动作之后。

## 自测

```bash
.venv/bin/pytest tests/ -q
```

- `tests/test_planner.py`（9 项）：最优装带数、回卷顺序、平局裁决（回卷 vs 多装一带）、
  无副本文件单列、空计划、12 卷精确覆盖、副本分散时单卷最优、当前卷免装带。
- `tests/test_api.py`（24 项）：
  - 目录登记与校验（空目录 / 重复副本 / >12 卷 / 有作业或送检卷时不可替换）；
  - 下架通过后立即离线；拿走最后一份可读副本时**整批退回**；
    超集批次中含安全卷也不放行；送检卷上的副本不计入“最后一份”；
    占用卷导致退回并列出受影响文件与占用卷；
  - 逐卷归还、按卷号归还、重复归还 409、跨申请归还 422、申请不存在 404；
  - 开工快照只含当时在线且未报坏副本；归还的卷不补进已开工作业；
    仅剩坏/离线副本的文件进入无副本清单；
  - 坏副本在目录中标为不可读、不再占用卷；坏副本不算“最后一份”；
    下架当前挂载卷时带头复位；作业作废释放占用；
  - 3 组并发交错测试（审批 vs 开工、归还 vs 再次下架、坏回执 vs 下架），
    各跑 20 轮，断言不存在“离线卷仍被占用/仍可用”或“文件失去全部在线可读副本”。
- `scripts/walkthrough.py` 对运行中的服务走完整个流程：登记目录 →
  两次被退回的整批下架（最后副本 / 占用卷）→ 7 步回执（含两次读坏）→
  送检卷2 并归还 → 重新开工。

## 遗留事项

1. **实际读带流程中回卷永不触发**：计划按升序调度且失败副本即停用，
   “当前卷上存在带头之下的可用副本”这一回卷前提在回执流中不可达。
   回卷分支仅为理论完备性保留（见 `tests/test_planner.py`）。
2. **状态仅存内存**：单作业、重启即丢；如需持久化或多作业并行需引入存储层。
3. **装带/回卷视为必然成功**：真实驱动器可能有机械故障，模型未覆盖。
4. **同位置多副本**：允许不同文件登记相同 (卷, 序号)，视为先后可读（带头语义为
   “最后读到的序号”）；如需严格物理语义可改为带头 = 序号 + 1。
5. **无鉴权**：默认内网值班室使用；对外暴露需自行加认证。
6. **本机无 Docker**：`docker compose up` 未在本机执行；运行期行为以本地
   uvicorn + 测试 + walkthrough 验证。Dockerfile 与 compose 文件未改动。
